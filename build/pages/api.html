Data API

Every table, as JSON

The index is published as static JSON files under /api/v1/. No key, no tracking, no rate limit beyond what a static host imposes. Fetch them from a browser, a spreadsheet, a notebook or a build pipeline. Version 1 only ever adds fields; it never renames or removes them.

Example

Fetch the index and price it on your grid

Two requests, one multiplication. Energy per million tokens times the grid's grams per kWh, divided by 1,000, is kilograms of CO2e per billion tokens.

curl -s {{SITE}}/api/v1/index.json | jq '.rows[] | select(.slug == "{{REF_SLUG}}")'
curl -s {{SITE}}/api/v1/grid.json  | jq '.areas[] | select(.iso3 == "SRB")'

The first returns the reference model's rows (one per GPU); the second returns Serbia at {{SRB_G}} gCO2e per kWh. {{REF_WH_1}} × {{SRB_G}} ÷ 1,000 = {{REF_KG_SRB}} kg CO2e per billion output tokens on the H100 row.

From a browser

CORS is open

The files are served by GitHub Pages, which sends access-control-allow-origin: *, so a page on any origin can fetch them directly.

const r = await fetch("{{SITE}}/api/v1/index.json");
const { rows } = await r.json();
const best = rows[0];   // sorted ascending by Wh per million output tokens
console.log(best.model, best.gpu, best.wh_per_million_output_tokens);

Python

import json, urllib.request

BASE = "{{SITE}}/api/v1/"
index = json.load(urllib.request.urlopen(BASE + "index.json"))
grid = {a["iso3"]: a for a in json.load(urllib.request.urlopen(BASE + "grid.json"))["areas"]}

row = next(r for r in index["rows"] if r["slug"] == "{{REF_SLUG}}" and r["gpu"] == "H100")
kg = row["wh_per_million_output_tokens"] * grid["SRB"]["g_co2e_per_kwh"] / 1000
print(row["model"], row["num_gpus"], "x", row["gpu"], round(kg, 1), "kg CO2e per billion output tokens in Serbia")
print(index["caveat"])

Fields

What the columns mean

One table for the fields every document carries, then one per document. The build refuses to publish a field that has no description here, and openapi.json and types.d.ts are generated from the same documents, so the three cannot drift apart. joules_per_output_token is published to seven decimals, so wh_per_million_output_tokens = joules × 1,000,000 ÷ 3,600 holds exactly on every row.

Versioning and licence

Additive only

Caching and limits. The files are served by GitHub Pages, which sends Cache-Control: max-age={{PAGES_MAX_AGE_S}}, an ETag and Last-Modified. Poll with If-None-Match, no more than hourly, and mirror the files rather than fetching them for each of your users: the host has a soft bandwidth limit of {{PAGES_BANDWIDTH_GB}} GB a month and does not allow software-as-a-service use. There is no uptime promise. The data is refreshed when a source publishes a new release, checked monthly; the date is in every document and in changes.json.

Version 1. Fields are added, never renamed or removed. A new source or a re-measurement changes values, data_version and the updated date, and the change is recorded in changes.json and on the index's change list. row_id identifies a row across releases. A breaking change would ship as /api/v2/ with v1 left in place.

Licence. The compilation, the derived figures and the site text are offered under CC BY 4.0: use them, credit Lead Green and the underlying source. Each source keeps its own licence, stated per source in manifest.json with the evidence. ML.ENERGY: {{MLE_LICENCE_SENTENCE}} Ember's data is CC BY 4.0. AI Energy Score: Apache-2.0 as tagged on the Hugging Face Space; the project states no separate licence for the results file, which is reproduced as facts with attribution.
